# 도로명변환기 iPhone OCR 시험판

순수 정적 웹 페이지. 원본 안드로이드 저장소를 변경하지 않고 OCR 적합성부터 검증하는 별도 시험판입니다.

## 구현 범위

- 후면 카메라, 화면 확대, 촬영 정지, 사진 선택, 기본 카메라 대체 입력
- 드래그 영역 지정, 전체 선택, 90도 회전
- PaddleOCR 한국어 PP-OCRv5 + ONNX Runtime Web WASM / Tesseract 한국어·영어 비교
- 모델 준비 시간과 실제 추론 시간 분리, 원문 결과·복사, 취소·90초 제한
- 홈 화면 설치용 manifest와 아이콘, 선택적 오프라인 다운로드, 서비스워커 캐시
- 이미지·인식 결과는 메모리에만 유지. 사용자 사진을 서버에 전송하는 코드 없음
- 안드로이드 내장 사전(2026-09-14)의 20,155개 지역명을 별도 경량 데이터로 제공.
  OCR이 `운극동`을 읽으면 문맥상 `원곡동`을 후보로 표시하지만 선택 전에는 원문을 바꾸지 않음.
  설정에서 근무지역을 지정하거나 OCR 결과에 시군구가 있으면 그 지역의 후보만 표시.
  원문과 숫자, 수취인 이름을 자동으로 변경하지 않음
- 실제 지번↔도로명주소 변환·제비쨩 노트는 이 시험판 범위 아님

## 실행 및 배포

`dist`를 HTTPS 정적 서버로 제공합니다. 빌드 단계나 런타임 서버는 필요하지 않습니다.
파일은 모두 같은 출처에서 제공하며 OCR CDN·외부 API에 런타임 의존하지 않습니다.
`.openai/hosting.json`은 Sites 프로젝트와 정적 출력 디렉터리를 지정합니다.
추후 Cloudflare Pages에서도 `dist`를 그대로 배포할 수 있습니다.

`scripts/fetch-assets.py`는 고정된 공식 모델과 실행 파일을 재다운로드합니다.
Python 3 및 PyYAML이 필요합니다. 사전은 반드시 해당 모델의 inference.yml에서 추출합니다.

## 검증 및 한계

Node에서 브라우저와 같은 ONNX Runtime Web WASM 및 공유 전·후처리 코드를 실행해 합성 한글 사진의 실제 검출·인식을 검증했습니다.
예제는 안산시 주소 형태를 사용한 합성 자료이며 실제 우편물 또는 실제 주소 존재를 보증하지 않습니다.
아이폰 실기기 카메라, Safari Worker 실행, 메모리, 온도, 서비스워커 설치·오프라인 복귀는 사용자 기기에서 확인해야 합니다.
허용된 브라우저 검증 환경을 사용할 수 없어 화면 및 WebMCP 런타임 검증은 수행하지 못했습니다.

PaddleOCR 검출 후처리는 DB 확률맵 연결요소 + 최소 면적 사각형 + 직사각형 확장 방식입니다.
공식 DBPostProcess의 폴리곤 offset 방식과 완전히 같지 않으므로 성능 평가는 이 웹 구현 전체 기준으로 해야 합니다.
기울어진 사각형은 회전 보정하지만 종이의 심한 원근 왜곡은 별도 보정하지 않습니다.
인식 점수는 모델 자체 점수이며 정답률이 아닙니다. OCR 원문을 임의로 주소·이름 교정하지 않습니다.
첫 버전은 WASM 단일 스레드 CPU 기준이며 WebGPU는 아직 적용하지 않았습니다.
Service worker 캐시는 버전별로 관리합니다. 정적 자원 변경 시 app.js와 sw.js의 CACHE 값을 함께 올립니다.

## 현장 확인 순서

1. Safari에서 열고 예제 사진으로 PaddleOCR·Tesseract 비교
2. 실제 인쇄 주소를 촬영하고 영역 지정 후 번지·부번·동호수 비교
3. 같은 사진으로 반복 인식하여 최초 준비 시간과 재사용 시간 구분
4. 홈 화면 설치 후 그 앱에서 오프라인 준비를 완료
5. 비행기 모드에서 종료·재실행 후 인식
6. 연속 촬영, 화면 잠금·복귀, 카메라 권한 거부 후 사진 선택 시험

데이터셋 확보 전에는 인식률·아이폰 소요시간 수치를 일반화하지 않습니다.
